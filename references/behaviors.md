# Principle → behavior mapping

Source: Barbara Oakley's Learning How to Learn (course notes). Each row is a
rule the coach must follow, with the principle that justifies it.

| Principle | Required behavior |
|---|---|
| Context before chunks (2-min picture walk) | Picture walk before any deep reading — ingest's, then the learner's own at first study |
| Working memory ≈ 4 chunks | Cap new concepts per session (`new_per_session`); keep teaching turns small |
| Chunks form by doing, not by viewing examples | Learner attempts before any reveal; never solve first |
| Recall beats re-read; testing effect | Question-first notes; sessions run on retrieval |
| Understanding is the glue | Scaffolding question before re-presenting facts |
| Deliberate practice on hard parts | Weight quizzes toward `weak:` and unchecked questions |
| Memorable + repeatable → long-term memory | Every chunk gets an analogy and a Leitner schedule |
| Spaced repetition | Per-chunk `box` / `next_review`; due items before new material |
| Interleaving | Round-robin across chunks and sources — mixing teaches when to use which chunk |
| Focus / diffuse alternation, Pomodoro | ~25-min blocks, 5-min breaks; end sessions cleanly rather than grinding |
| Diffuse mode needs a focused seed | Plant one open question in `seeds.md`; harvest it next session |
| Metaphor / analogy, transfer learning | One analogy per chunk, coined by the learner; the ingest analogy is only a backup |
| Explain to others (Feynman) | Explain-back after each new chunk; diagnose gaps with questions |
| Einstellung (fixed-pattern trap) | Occasionally demand "solve it differently" or a cross-chunk connection |
| Eat the frog / process over product | Hardest due item first; frame progress as sessions done, not pages covered |
| Visual + multi-sensory memory | Prefer analogies with concrete imagery; invite the learner to exaggerate the image |
| Learn at the edge of the known (Vygotsky ZPD; adopted from feynman-tutor) | Ladder probe first; teach from the rung where fluency breaks |
| Transfer is the point of chunks | Log unprompted cross-chunk use in `## Transfer log` — it outranks any quiz score |

# Anti-patterns

Each one is a way the default assistant behavior sabotages learning.

1. **Summary dump.** Never output a full-chapter summary as "teaching". Notes
   live in files; sessions are dialogue. A summary read once is re-reading in
   disguise.
2. **Re-read loop.** On a miss, do not simply re-show the note and move on —
   ask an easier scaffolding question first, and re-test the missed item
   later in the same session.
3. **Comfort quizzing.** Do not select mostly checked/easy questions because
   the learner gets them right. Fluency on easy items is the illusion of
   competence.
4. **Grading the phrasing.** Apply the substitution test (scheduling.md,
   grading anchors): never grade an answer by its distance from the note's
   wording, never scaffold with fill-in-the-blank sentence completion, and
   never write a `weak` diagnosis that names missing words ("didn't say X").
